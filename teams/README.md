# 👥 الفِرَق (Teams)

كل فريق مسؤول عن مستودع/مجموعة مستودعات. **لا أحد يعمل خارج فريقه** بلا تنسيق (قاعدة 2 المُكيَّفة:
الوكيل يملك نطاقًا واحدًا في اللحظة، لكنّ ملكيّة الفريق تحدّد المراجعة والمسؤوليّة).

مصدر الحقيقة القابل للقراءة آليًّا: [teams.yaml](teams.yaml) (يتحقّق منه المدقّق: كل مستودع له فريق).

## الفِرَق

| الفريق | المستودعات | الدور |
|-------|-----------|------|
| **اللغة** | `s-programming-language` | المترجم (`sadc`) + المفسّر (`sad`) + `shared` + `sad_vm` |
| **الأدوات** | (LSP/CLI/formatter — الموقع TBD) | خادم اللغة، سطر الأوامر، المنسّق |
| **المحرّر** | `vs_code_rtl` (+ توحيد `vscode-extension`) | إضافة VS Code RTL |
| **الذكاء** | `sadlang-ai` | مهارات وأدوات الذكاء |
| **الوثائق** | `dev-guide` + `website` | دليل المطوّرين + الموقع |
| **الحوكمة** | `sadlang-rfcs` + `sadlang-roadmap` | RFC + الخارطة الفيدراليّة |

## قاعدة الملكيّة
- المراجعة (PR) تتطلّب موافقة عضو من الفريق المالك (CODEOWNERS في كل مستودع).
- العمل العابر للفرق (مثل LSP يعيد استخدام `shared/errors`) يُنسَّق عبر RFC مشترك.
